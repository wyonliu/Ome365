# Ome365 v1.2 · 90-day preview · what comes after team-brain

> v1.1.0-v1.1.3 (May 2026) shipped Team Brain + productization + enterprise polish
> in a single sprint: 433/433 tests · 0 PII · 12 v1.1 modules. v1.2 is the
> next 90 days (June–August 2026).

## Tagline

**v1.1 = team brain. v1.2 = team conscience.**

If v1.1 makes the *decisions* explicit, v1.2 makes *what was learned from them*
explicit. Decisions decay; patterns persist; conscience compounds.

---

## Three themes

### Theme A · Cognition Loop (the conscience)

Every closed Decision in v1.1 has §⑧ Feedback that's currently empty (pending
90-day backfill). v1.2 wires the loop:

- `ome365 distill` · once-a-quarter scan of all Decisions where 90+ days have
  passed since close, prompting LLM (Karpathy-style) for what actually
  happened vs predicted, writing back to §⑧ in-place.
- `ome365 conscience` · weekly digest of "decisions that didn't pan out",
  formatted as a 3-page reflection report. Same 8-step decision template gets
  reused for the meta-decision "should we keep doing X?".
- Auto-supersede suggestions: when a new Decision's outcome contradicts an
  old one's outcome, propose `superseded_by` in the new one's frontmatter.

### Theme B · Multi-Hike federation (the network)

v1.1 ome365.id + ome365.a2a are stub. v1.2 ships the real thing:

- **ome365.id real** · ed25519-signed W3C DIDs (we already have the
  signing in v1.1.2 — just need to apply it to identities). 4 Skill VC
  types: `Skill.authored`, `Skill.adopted`, `Skill.contributed`,
  `Skill.distilled`.
- **ome365.a2a real federation** · 2-instance demo where alice@orgA and
  bob@orgB co-author a shared skill, signed by both DIDs. T2-tier
  pinlist verification using the v1.1 signing infrastructure.
- **Cross-org SKILL.md adoption tracking** · `Trace/<date>.jsonl` already
  has skill name + actor; v1.2 adds `actor_did` so federation can prove
  who used what.

### Theme C · Cost-per-Outcome FinOps board pack (the dollars)

v1.1.x has the metric. v1.2 has the **board-ready output**:

- `ome365 board-pack --period 2026-Q2` · generates a 4-slide PDF/HTML deck
  with per-team `cost_per_resolved_decision` benchmarked against
  `industry-benchmarks.yml`, exec summary, anomaly callouts.
- Industry benchmark refresh SOP · monthly nightly job that pulls latest
  Salesforce / NavyaAI / Forrester numbers and updates the YAML.
- CFO quarterly review template · `vault/Board/<quarter>.md` with auto-
  populated tables that the CFO can edit-in-place before the meeting.

## What v1.2 explicitly does NOT ship

- **HR module** · Ome365 stays out of formal HR. We provide *resource
  allocation hints*, the eval policy is firm. Anything HR-shaped (PIPs,
  comp recommendations, termination support) is forbidden by
  `docs/policies/EVAL_USAGE_POLICY.md` and remains so.
- **Real-time collab editing** · Yjs/CRDT was already cut from v1.1
  (`Decisions/cut-feature-realtime-collab.md`). Same answer: git is good
  enough for file-first vault; async wins.
- **Self-hosted LLM** · we recommend Ollama as the local default; we
  don't ship a competing stack. v1.2 deepens API-key integration but
  doesn't try to be Ollama.

## Decision dependencies

These are the v1.1.x Decisions whose 90-day Feedback (§⑧) feeds v1.2:

- `2026-05-08-pick-llm-backend` (W1) — does Anthropic Haiku 4.5 actually meet
  cost targets in 90 days of real usage?
- `2026-05-09-trace-sdk-design` (W3) — does context manager pattern survive
  high-QPS prod load?
- `2026-05-09-eval-w4-d4-and-dashboard` (W4) — does anchor-based D4 actually
  reduce social-proof bias vs the v1 outcome-string approach?
- `2026-05-09-wiki-update-query-impl` (W6) — does rule-based distill produce
  patterns teams actually re-read, or is LLM-distill (P3 #15) needed to make
  the wiki useful at scale?

These will be auto-distilled by `ome365 distill` in v1.2 and feed back into
the design doc itself. **The wiki is the artifact** — v1.2 closes the loop.

## How this preview becomes a plan

This file is `r0.1-draft`. Real planning kicks in after:
1. v1.1.3 has been in real-team use for 14 days
2. We've collected feedback from at least 5 real adopters
3. CFO/CIO interviews on board-pack format priorities
4. Architecture review on federation real signing path

When that's done, this file is rewritten as `MASTER-PLAN-v1.2.md`. Until
then: **resist the urge to over-plan**. v1.1 worked because we shipped first
and reviewed second.
