## 一 · 设计原则（v1.0 沿用 + v1.1 强化）

| # | 原则 | 含义 | 没遵守的代价 |
|:---:|:---|:---|:---|
| 1 | **file-first** | 所有信息以 markdown 落盘 | 失去 git diff / rsync / audit 优势 |
| 2 | **派生 lazy 计算** | 7 维评分等永不写盘 | vault 不再是 ground truth |
| 3 | **零强制启用** | 4 文件夹都可选·缺了也跑 | 单用户场景被组织功能压重 |
| 4 | **Anthropic 标准兼容** | SKILL.md 完全兼容 skills.sh 格式 | 生态分裂·失去 ecosystem |
| 5 | **append-only logs** | Trace/ 只能 append·不能 update/delete | 评分可被人工篡改 |
| 6 | **GDPR Art. 22 合规** | 评分不可作为人事决策唯一依据 | 法律风险·OSS 责任 |
| 7 | **tenant-scoped** | 所有派生函数接 tenant_slug | 多租户数据混淆 |
| 8 | **可演进的 schema** | frontmatter 字段可加不可删 | 旧 vault 不向后兼容 |

## 二 · 8 套专家评审 · 真实发现 + 吸收方案

下面每个专家视角是真发现的问题（不是装腔），每条都有"吸收"对应。

### 2.1 架构师视角（极简性）

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| Members/ 与 Contacts/people/ 重复·应复用 | 🔴 | **取消 Members/ 文件夹**·只用 Contacts/people/·加可选 employment 字段 |
| Trace/<date>.jsonl 长期累积会爆 | 🟡 | 自动 monthly rollup → Trace/monthly/<YYYY-MM>.summary.json·原始 jsonl 可压可归档 |
| Decisions/ 在 vault 根 vs 在 Knowledge/ 下 | 🟢 | 放 vault 根（与 Notes/Journal 平级）·决策不是知识·是流程产物 |
| eval scoring 规则硬编码 | 🔴 | 走 vault/.ome365/eval-config.yml·tenant 各自配 |

### 2.2 安全专家视角

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| Trace 含 cost / output_value 商业敏感 | 🔴 | Trace/ 默认 owner-only access·跨人查询需 admin |
| Members 评分查询暴露 ranking 信息 | 🔴 | /api/eval/* 默认 admin-only·普通成员只能查自己 |
| Trace append-only 靠约定不可靠 | 🟡 | 提供 git pre-commit hook 校验 Trace/ 只 append（diff line count）|
| 派生评分缓存层无访问控制 | 🟡 | 派生函数永不缓存到磁盘·永远 lazy（已是设计·强化文档）|

### 2.3 HR/组织专家视角

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| 7 维权重 baked in 不切实际 | 🔴 | 走 eval-config.yml·权重可改·提供 5 个 preset（engineer/PM/sales/ops/mixed）|
| 永不写盘 vs 季度/年度 review 需冻结 | 🔴 | 加 opt-in `Eval/snapshots/<period>/<member>.md`·手动触发·不自动 |
| 离职/复职 single date 处理不够 | 🟡 | employment_history 列表（参考 LinkedIn）：每条 {company, title, from, to} |
| 评分暴露给同事会引发恶性比较 | 🔴 | UI 默认显示自己·上级看下属·绝不全员排行榜（移除 leaderboard 的 member ranking）|

### 2.4 OSS 产品专家视角

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| "Members" 概念对个人用户太重 | 🔴 | 4 文件夹全可选·v1.0 install 不创建·setup wizard 才提示 |
| Anthropic SKILL.md 兼容性需要实证 | 🔴 | 真在 Claude Code 跑通 1 个 Skill·CI 加这个验证·不是嘴上说兼容 |
| Skills/ 在 vault 还是 repo？ | 🟡 | **两种都支持**·skills.sh 上传走 repo·私有走 vault/Skills/·仅 path 不同 |
| v1.1 不是 HN 王炸级新功能 | 🟢 | 接受·v1.1 是"组织友好"·不是"震撼"·震撼留给 v1.2 federation |

### 2.5 企业部署专家视角

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| Trace global vs per-tenant | 🔴 | per-tenant：vault/<tenant>/Trace/ 已是·确认设计·写入文档 |
| eval_member 跨租户语义模糊 | 🔴 | 函数签名强制 (tenant_slug, member_id)·禁止 tenant=None |
| Decisions 跨租户（A2A 联邦）后续怎么办 | 🟡 | v1.1 不解决·v1.2 federation 时再处理·标 known limit |
| Members schema 多租户差异 | 🟡 | tenant_config.json 可声明 member_extra_fields·允许 frontmatter 扩展 |

### 2.6 DX 专家视角

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| 4 个 schema 学习成本 | 🟡 | 提供 `./ome365 init Members/Skills/Decisions` 命令·一次创建样本 + README |
| Trace 怎么 append？SDK 还是 CLI？ | 🔴 | 提供 Python SDK：`from ome365 import trace; trace.log(...)` + CLI `./ome365 trace add` |
| 100k Trace 行的查询体验 | 🟡 | 提供 `./ome365 trace query --since --actor --skill` 命令·内部 grep+jq |
| schema validation 强制 vs 警告 | 🟢 | 警告级·不阻塞·错了 cockpit 显示 invalid badge 但不崩 |

### 2.7 法律/合规专家视角

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| GDPR Art. 22 自动决策禁令 | 🔴🔴 | /api/eval/* 响应**强制**含 `"human_review_required": true`·UI 强制显示警告 |
| EU region 自动决策禁用 | 🔴 | tenant_config.region=EU 时·eval API 默认 disabled·需爸爸明文 enable |
| PIPL §38 跨境评分 | 🔴 | Trace/Decisions/Eval snapshots **默认禁止跨租户传输**·a2a federation 不传 eval 数据 |
| 评分用作 KPI 的边界 | 🔴 | docs/legal/EVAL_USAGE_POLICY.md 模板·部署方签 |

### 2.8 数据科学/Eval 方法论专家视角

| 发现 | 严重度 | 吸收 |
|:---|:---:|:---|
| 0-5 单点评分统计上不可靠 | 🔴 | 评分必须返回 (raw_metric, score, percentile_within_team, sample_size)·不是单数字 |
| 单 snapshot 噪音大 | 🔴 | 默认走 30-day rolling window·snapshot 接 ?window= |
| D5 fork count 可被刷 | 🔴 | adoption_count = unique distinct caller actors·不是 raw fork |
| 跨团队不可比 | 🟢 | percentile within team only·不跨团队 ranking |

### 3.1 文件夹约定（vault 内）

```
vault/                              # 已有（v1.0）
├── Journal/                        # 已有
├── Notes/                          # 已有
├── Memory/                         # 已有
├── Knowledge/                      # 已有 · 加子目录约定
│   ├── L1-raw/                    # 原始资产·永不删
│   ├── L2-distilled/              # 结构化语料·从 L1 蒸馏
│   └── L3-diagnostic/             # Agent 直调的旗舰场景
├── Contacts/people/                # 已有 · 升级为成员档主体
│
├── Skills/                         # 🆕 v1.1 可选 · Anthropic SKILL.md 兼容
│   ├── meeting-summarize.md
│   └── code-review.md
├── Decisions/                      # 🆕 v1.1 可选
│   └── 2026-05-08-vendor-pick.md
├── Trace/                          # 🆕 v1.1 可选
│   ├── 2026-05-08.jsonl           # 当日流水
│   └── monthly/
│       └── 2026-05.summary.json   # 月底自动 rollup
└── Eval/                           # 🆕 v1.1 可选
    └── snapshots/                  # 手动触发的评分冻结
```

**关键决策**：
- Members 取消·复用 Contacts/people/（架构评审 2.1）
- 4 个新文件夹全部可选·缺一个不影响其他
- v1.0 install 默认不创建这 4 个·`./ome365 init team-brain` 才创建

#### 3.2.4 `Trace/<date>.jsonl` · per-line schema

### 3.3 Python 模块 · `.app/ome365_eval.py` · ≤ 200 行

```python
"""
ome365.eval · Lazy member/decision/skill/finops scoring from vault filesystem.
v1.1 · pure derivation · no DB · no caching to disk.
GDPR Art. 22 compliant: all responses include human_review_required=True.
"""

def eval_member(
    tenant: str,
    member_id: str,
    *,
    window_days: int = 30,
    weights_path: Path | None = None,
) -> dict:
    """
    Compute 7-dim eval for a member.
    Returns: {
        "tenant": "acme",
        "member_id": "alice",
        "window_days": 30,
        "dimensions": {
            "delivery":    {"raw": 12, "score": 4.2, "percentile": 0.78, "n": 23},
            "ai_efficacy": {"raw": 18.5, "score": 3.8, ...},
            ...
        },
        "weights_used": {...},
        "human_review_required": True,            # GDPR Art. 22
        "computed_at": "2026-05-08T...",
        "warning": "Eval is for resource allocation hint only. NEVER use as sole basis for HR decisions.",
    }
    """

def finops_summary(
    tenant: str,
    *,
    scope: Literal["all", "by_actor", "by_skill", "by_decision"] = "all",
    since: date | None = None,
) -> dict:
    """ROI dashboard data · pure scan over Trace/."""

def decision_lifecycle(
    tenant: str,
    decision_id: str,
) -> dict:
    """Read Decisions/<id>.md · parse 6 sections · return timeline."""

def snapshot_create(
    tenant: str,
    period: str,                              # "2026-Q2"
    members: list[str] | None = None,         # None = all
) -> Path:
    """Manual opt-in snapshot · writes Eval/snapshots/<period>/*.md ·
       freezes lazy scores at this point in time."""
```

### 3.4 配置 · `vault/.ome365/eval-config.yml`

```yaml
# Per-tenant eval configuration · loaded by ome365_eval.py
# 5 preset · choose one or write your own
preset: engineer  # engineer | pm | sales | ops | mixed

# Override (覆盖 preset 默认权重)
weights:
  delivery: 0.15
  ai_efficacy: 0.15
  quality: 0.15
  judgment: 0.10
  ecosystem: 0.25
  business_impact: 0.10
  learning: 0.10

# Window 控制
default_window_days: 30
sample_size_min: 5  # n < 5 时·score 返回 null + reason="insufficient_sample"

# 区域合规
region: cn  # cn | eu | us · EU 时 /api/eval/* 默认 disabled
```

### 3.5 API 端点 · 3 个

```
GET  /api/eval/member/{member_id}?window=30      # eval_member()
GET  /api/eval/finops?scope=by_actor&since=...   # finops_summary()
GET  /api/eval/decision/{id}                      # decision_lifecycle()
POST /api/eval/snapshot                           # snapshot_create()
```

**默认权限**：
- `GET /eval/member/{me}` → 自己的成员可看
- `GET /eval/member/{other}` → admin only
- `GET /eval/finops` → admin only
- `POST /eval/snapshot` → admin only
- `region=EU` 时全部 403 · 需 tenant_config.eval_enabled_eu=true 才开
