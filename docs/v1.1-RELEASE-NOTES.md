## Design pillars

### 1. Anti-Tokenmaxxing

Cost-per-Outcome (USD per resolved decision) is the headline metric — not
tokens consumed. We deliberately avoid token leaderboards because performative
AI usage corrupts the measurement (see Meta 2026-04 incident, Pinnacle
critique).

### 2. File-first vault

Every artifact (decision, trace, audit log, distilled wiki, agent card) lives
on the filesystem as Markdown or JSONL. No DB. `git log` is your audit trail
for code; `vault/Audit/<date>.jsonl` is your audit trail for runtime.

### 3. ed25519-signed agent cards

Every Ome365 instance generates a per-vault ed25519 keypair on first run and
signs `/.well-known/agent-card.json`. Cross-org A2A protocol can verify
identity without a central PKI.

### 4. Default-deny region-aware compliance

GDPR Art. 22 → default-deny EU evaluations. PIPL §13/§24 → ack-required CN
evaluations. Both are policy decisions that ship in code.

### 5. Kevin "先文件再代码" rule

Every code commit cites a Decision via `[decision: <id>]`. Git hook in
`.githooks/commit-msg` enforces. Bypass with `OME365_NO_DECISION=1`. The full
8-section Decision template ships in `vault.example/Decisions/`.

## Performance

- 194× cache speedup proven via `_compute_team_distribution()` single-pass
  (perf benchmark in `scripts/perf_bench.py` · 1000 decisions / 50 members)
- Async trace via `queue.Queue` daemon thread (1ms enqueue vs 100ms+ disk fsync)
- Metrics CLI dumps Prometheus text without server boot (cron-friendly)

## Operational scriptability

Every mutating CLI supports `--dry-run`:

```bash
ome365 wiki update --dry-run     # preview distillation
ome365 archive --dry-run         # preview rollup
ome365 backup create --dry-run   # preview tarball
ome365 backup restore X --dry-run  # preview extract
```

Every output CLI supports machine-readable JSON:

```bash
ome365 doctor --json
ome365 backup list --json
ome365 wiki query 'X' --json
ome365 decision list --json
ome365 rbac who alice  # always JSON
ome365 notify test     # always JSON
```
